## 0. 一句话定位

一个 **0.19B、无外部 LLM** 的关系路径条件化判定器，可作为**即插即用重排层**，
在不改动任何检索器的前提下把候选 H@1 提升 **+4.4 ~ +5.2pt（p<1e-6）**，代价仅 **+26ms/题（批量；串行上界 428ms）、+2.2GB**。

## 2. 摘要草稿

现有 KGQA 的强结果依赖 7B 级 LLM 生成关系路径（RoG 等），推理成本高且不可迁移。
我们发现：**候选排序阶段缺失的关键信号是"关系路径"本身**——把路径写进判定 prompt，
一个 0.19B 的循环主干就能在候选内部把 H@1 从 41.98% 提到 55.91%（WebQSP，+13.93，p=2.0e-29），
MetaQA 从 66.60% 提到 88.20%（+21.60，p=1.5e-71）。
这个判定器**不需要与检索器同源**：把 RoG-7B 检索出的候选交给它重排，
H@1 从 60.9% 提到 66.1%（+5.16pt, p=8.5e-7）；候选翻倍时从 47.7% 提到 66.7%（+18.9）。
整套系统单题 **278ms / 2.2GB**（beam 73 + 打分 205），当作重排层插入的边际成本仅 **+26ms/题**。
我们进一步给出失效边界：CWQ 正例率仅 1.07% 时该信号失效（−1.1pt），
WebQSP 2 跳只 +3.5pt 而 1 跳 +18.2pt——**正例密度与路径长度共同决定收益**。

## 4. 方法

### 4.1 共享主干的游走器
- RWKV-7 0.19B（191M），VGHN 关系头打分 → beam 200 / topk-rel 15 / max-children 128 / max-hops 2
- 输出 top-200 候选，每个候选带一条关系路径

### 4.2 路径条件化判定器
```
Question: {q}
Relation path: {r1 -> r2}
Candidate: {e}
Is this the final answer?
```
- 同一主干，线性二分类头（`logit[1]-logit[0]`）
- 训练：题内 listwise softmax，2812 题，3 epoch，lr 2e-6，7 分钟

### 4.3 可插拔用法
- 输入：任意检索器给出的 (question, candidate, path) 三元组
- 输出：重排分数；不改检索器、不重训
- 成本：+26ms/题（15.7 候选，按题批量；逐候选串行则 +428ms）
- 关键结构性优势：判定器每候选一次前向、无自回归解码 → 一题候选可整批打分；LLM 生成器逐 token 解码，无法这样批

## 5. 实验

### 5.1 主表（WebQSP test，n=1627，vt=200）
| 系统 | H@1 | H@5 |
|---|---|---|
| 原基线（plain 判定器） | 44.19 | — |
| + VGHN 关系头 | 47.94 | — |
| + path 判定器 | 56.12 | — |
| + SetRank | 57.22 | 70.37 |
| **+ 主干端到端微调（最终）** | **58.03** | **71.9** |

### 5.2 同池单变量消融（n=1615）
walker 17.8 → plain 42.0 → path **55.9** → +SetRank 57.6 → 微调 **58.5**

### 5.2b path 条件化的跨数据集复现（核心论据）
| 数据集 | plain | path | Δ | 显著性 |
|---|---|---|---|---|
| WebQSP（top-200 池，n=1615） | 41.98 | **55.91** | **+13.93** | p=2.0e-29，CI [+11.52,+16.35] |
| MetaQA（**全量 14,274**） | 65.86 | **87.97** | **+22.11** | 2k 子集 +21.60，p=1.5e-71 |
| CWQ（n=3520，正例率 1.07%） | 26.31 | 25.23 | −1.08（失效） | — |

- seed 稳定性：path 判定器 3 seed **0.5489±0.0013**；MetaQA 4 seed **0.8898±0.0111**

- 解读：关系空间越小、路径越干净，路径信号的增益越大；CWQ（正例率 1.07%）则失效 → 三者共同给出"何时有效"的判据

### 5.3 可插拔（核心实验）
| 底座检索器 | 候选/题 | 原 H@1 | +我们 | Δ | p |
|---|---|---|---|---|---|
| RoG-7B（beam 3） | 15.7 | 60.93 | **66.09** | +5.16 | 8.5e-7 |
| RoG-7B（beam 10） | 30.3 | 47.73 | **66.65** | **+18.92** | — |
| 我们的 walker（同源） | 200 | 41.97 | 55.91 | +13.9 | — |
| RoG-7B + 冻结判定器（beam 3） | 15.7 | 60.93 | 65.36 | +4.42 | 2.6e-5 |

- **候选翻倍时，底座排序崩 13pt、我们几乎不动** → 额外召回只有配可靠判定器才能兑现（fig4）

### 5.4 迁移边界（重要负结果）
| 迁移方向 | 本地重训 | 零样本 |
|---|---|---|
| 跨检索器（walker → RoG-7B，同一 KG） | — | **+5.16pt（成功）** |
| WebQSP → MetaQA（path prompt） | **0.8820** | **0.30（失败）** |
| WebQSP → CWQ（path prompt） | 0.2523 | **0.2412（失败）** |

- 解读：判定器学到的是"**该 KG 的关系模式**下的路径→答案映射"；
  换数据集 = 换关系命名与分布，必须重训
- 但重训极便宜：**7 分钟 / 数据集**（3 epoch × 数千题），换来 MetaQA +21.6pt
- 论文写法：不宣称"通用零样本"，而宣称"**跨检索器可迁移 + 每数据集 7 分钟适配**"

### 5.5 成本
| 项目 | 我们 | RoG-7B |
|---|---|---|
| 参数 | 191M | 7B |
| 单题延迟（按题批量） | **278ms**（beam 73 + 打分 205） | ≈620ms（仅路径生成，同卡实测） |
| 单题延迟（逐候选串行，上界） | 3.9s | — |
| 插入到 RoG 的边际成本 | **+26ms（批量）/ +428ms（串行）** | — |
| 峰值显存 | 2.2GB | 13GB |
| 外部 LLM | 无 | 需要 |

### 5.6 消融与负结果（全部进正文，不进附录）
- 集合自注意力（SetRank 的 enc）：−0.11pt → 无用
- 二阶段联合头 s2：5/5 seed 低于 stage-1 → 砍掉
- 答案类型约束：−0.43pt → 无效
- beam 400：负收益；max-children 128→512：0 变化
- CWQ path：−1.08pt（正例率 1.07%）
- **提示词呈现**（同配方）：rel 54.89 / short 55.87 / natural 56.48 / entity（含中间实体）56.36 → 不依赖 Freebase 命名，中间实体无额外收益
- **训练数据规模**：25/50/100% → 50.46 / 52.43 / 54.89（25% 仍 +8.5pt）
- **路径内容对照**：真路径 56.18 / 随机关系 39.52 / 实体遮蔽 42.10 / 无路径 48.30
- **候选数敏感性**：25/50/100/200 → 49.23 / 51.38 / 54.33 / 56.18
- **同参数量主干**：RWKV 55.50 / GPT-2 48.37 / Pythia 46.28
- **RPO 式难负例**：val in_cand 0.7796 → 0.7796，止损
- **topk-rel 15→25**：0.5713 < 0.5760，负收益
- **长会话状态摊销**：精度 −3.3~−6.7pt 且更慢，仅作 pilot

## 6. Limitations（必须诚实写）

1. **精度不是优势**：NSM 110M/68.7 在我们的参数量-精度图上支配我们；KGT5 60M/56.1 参数效率更高。
2. **不是新架构**：最终系统是"共享主干 + 路径条件化 + 线性头 + 端到端微调"，无新模块。
3. **CWQ 失效**：正例稀疏时路径信号被淹没；WebQSP 上 2 跳仅 +3.5pt。
4. **MetaQA 偏容易**：gold_in_cand≈99.8%，主要考验排序，不能代表开放域。
5. **插入成本非零**：+26ms（批量）/ +428ms（串行），不能说"零成本"。
6. **跨 KG 零样本失效**：必须按数据集重训（虽只需 7 分钟）。
7. **长对话状态复用未成立**：当前 kernel 下更慢，明确不宣称。

## 7. 相关工作定位（必须区分）

| 工作 | 与我们的区别 |
|---|---|
| RoG (ICLR'24) | 用 7B 生成路径；我们把路径当**排序信号**，0.19B，可插拔 |
| GNN-RAG | GNN 检索器 + LLM 推理；我们只做重排、不生成 |
| Setwise (SIGIR'24) | prompt 层 setwise 重排；我们是**单候选 cross-encoder**、零额外前向 |
| LADR (SIGIR'23) | Pareto 前沿的写法参照；任务不同 |
| KGT5 | 更小但 transductive；我们无实体表 |
| NSM | 更强但需实体表 + 110M；我们强调无 transductive |
| GRAPE (ICLR'26 撤稿) | 不可作为对比基线，正文只提"已撤稿" |
| EmbeddingRWKV | 文档检索的 reusable states；我们是 KGQA 候选重排，且实测无优势 |
