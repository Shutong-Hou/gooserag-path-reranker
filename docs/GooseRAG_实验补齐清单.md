## 2. P0：论文必需（缺了会被审稿人直接问）

### P0-1 显著性补全
- **MetaQA path vs plain 的逐题 McNemar + bootstrap CI**（现在只有汇总 H@1）
- **WebQSP 最终系统 vs 原始基线（44.19）的逐题配对**（现在只有 vs 冻结判定器）
- **可插拔两条曲线的 bootstrap 95% CI**（现在只有 McNemar p）
- 做法：eval 时 `--dump` 或直接落逐题 hit；复用 `analyze_significance.py`
- 成本：低（CPU/短 GPU）｜止损：无

### P0-2 同参数量 Transformer 对照（**最关键的一块**）
- 目的：证明增益来自「path 条件化 + 训练方式」，不是「RWKV 主干特殊」
- 做法：GPT-2 124M / Pythia-160M 用**同数据、同 prompt、同目标**训练判定器，在**同候选池**上比较 H@1
- 成本：中（需重新挖矿+训练两套）｜止损：若 transformer 明显更好，改写为「主干无关，path 是关键」
- 产出：一张表（RWKV / GPT-2 / Pythia × plain / path）

### P0-3 共享主干 vs 不共享
- 目的：支撑「零额外参数」这一成本卖点
- 做法：复制一份 191M 作为独立判定器，重训，比 H@1 与显存
- 成本：中｜止损：若共享掉点 >1pt，成本叙事要弱化
- 产出：参数/显存/精度三行表

### P0-4 判定器误差分解（WebQSP 全量）
- 三分类：召回 miss（gold 不在候选）/ 排序错（在候选但没排第一）/ 其它
- 顺带给出「path 修好了多少排序错、还剩多少」
- 成本：低｜产出：一张瀑布图或表

### P0-5 延迟与显存分解
- 486ms 拆成：walker beam / 判定器前向 / 后处理
- 2.2GB 拆成：权重 / 激活 / 缓存
- 成本：低｜产出：一张表

### P0-6 图 5/6
- fig5：MetaQA plain vs path（全量）
- fig6：**正例密度 vs path 增益**三点图（CWQ 1.07% / WebQSP 2.63% / MetaQA 高密度）——这是全文最有辨识度的一张图
- 成本：低

## 3. P1：显著加强论文（建议全做）

### P1-1 提示词呈现方式消融
- 变体：只有关系链（现状）/ 关系 + 中间实体（`Jamaica -[rel]-> X -[rel]-> ?`）/ 自然语言化
- 目的：证明「不是随便加字符串就行」，而是路径信息本身
- 成本：中（每个变体训一次判定器）

### P1-2 候选数敏感性（我们自己的系统）
- vt ∈ {50, 100, 200, 400}，val 决定、test 只报一次
- 目的：展示「精度-成本」前沿（配合 fig1）
- 成本：低（cache 复用，只重训 SetRank/判定器）

### P1-3 训练数据规模曲线
- 训练题数 {500, 1000, 2000, 2812} → H@1
- 目的：支撑「7 分钟/数据集即可适配」的说法
- 成本：中

### P1-4 MetaQA 按跳数分解（1/2/3-hop）
- 目的：证明 +22pt 不是只来自 1-hop
- 做法：从 KB 计算最短答案路径长度，分桶
- 成本：低（CPU）

### P1-5 鲁棒性小表
- 候选顺序打乱 / 路径截断到 1 跳 / 实体名大小写与别名扰动
- 目的：说明结论不是脆弱的工程巧合
- 成本：低

### P1-6 训练期 LLM 蒸馏（有风险，带门）
- 做法：用 RoG/LLM 给训练候选打软标签，蒸馏进 0.19B 判定器（**推理仍不用 LLM**）
- 预期：+1–3pt
- 成本：中高｜止损：若 <+0.5pt，放弃并写入负结果

### P1-7 判定器引导 beam（有风险，带门）
- 做法：walk 扩展时用判定器分做路径剪枝/重排，而非只做事后重排
- 预期：可能显著提升召回利用率
- 成本：中高｜止损：若 in_cand 不升或 H@1 不升，停
