### E25 长会话（历史摊销）pilot —— 负结果
- 目的：验证 RWKV 的状态复用能否在"长会话重排"里形成结构性优势
  （历史只编码一次 vs Transformer 把历史拼进每条候选 prompt）
- 设置：WebQSP test 30 题 × top-20 候选；历史 = 同实体问答，补齐到恰好 H 轮；
  三种模式：none / cat（历史拼进每条 prompt）/ state（历史编码一次，逐候选从状态续算）

| H | none 精度/延迟 | cat 精度/延迟 | state 精度/延迟 |
|---|---|---|---|
| 0 | 0.533 / 473ms | 0.533 / 483ms | 0.533 / 475ms |
| 16 | 0.533 / 473ms | 0.500 / 610ms | 0.500 / 952ms |
| 32 | 0.533 / 476ms | 0.467 / 645ms | 0.467 / 544ms |

- **结论 1（机制正确）**：state 与 cat 精度完全一致（0.500/0.500、0.467/0.467）
  → 状态携带的实现是对的（每候选克隆，避免原地更新污染）
- **结论 2（精度无用）**：带历史反而掉 3.3–6.7pt —— 判定器**没在带历史的样本上训练过**，
  且我们构造的历史与当前问题无关（只是同实体）
- **结论 3（成本无优势）**：batch=1 时 FLA 的单序列+缓存路径开销极大（~25ms/候选），
  state 反而更慢（H=16 时 952ms vs cat 610ms）；理论上"历史只付一次"的摊销
  被每候选的内核启动开销淹没
- **结论 4**：早期"cat 在 H≥16 崩塌"是 `max_len=320` 右侧截断造成的假象，已修正为 2048
- 处置：**廉价的"长会话加成"不成立**。要做成真贡献，需要
  (a) 多轮/省略式训练数据（让模型真的用到历史）、
  (b) 批量化的状态扩展（避免逐候选克隆）、
  (c) 对话式基准（CSQA/ConvQuestions），量级是 1–2 周，且不改善单轮精度
- 产物：`hist_amortize.py`、`hist_amortize2.json`、`hist_amortize2.log`

### E43 P1-7 判定器引导 beam（每跳按判定器分裁剪）
- 实现：`eval_e2e.py --guide --guide-top N`；每跳先按 walker 累积分取前 N 个 (entity, path)，交判定器打分后保留 top-beam
- 前 400 题（同口径，path 判定器 s42）：

| beam | 不引导 | 引导 | Δ |
|---|---|---|---|
| 200 | 0.6050 | 0.6050 | 0.00 |
| 50 | 0.5975 | 0.6100 | +1.25 |
| 20 | 0.5725 | **0.6125** | **+4.00** |

- **全量 1627 题复核（beam=20）**：不引导 **0.5378** → 引导 **0.5612（+2.33）**
- 对照：同 pool/prompt 的 beam=200 全量为 **0.5618** → **beam=20 + 引导 ≈ beam=200（差 0.06pt，10 倍搜索预算）**
- 结论：标准 beam 下引导无增益（判定器本来就会重排全部候选）；但在**窄 beam** 下引导把 beam=20 拉回 beam=200 的水平 → "用判定器换检索预算"成立
- 性质：确认（**正负两面都记录**）
- 产物：`p17_base400.json`、`p17_guide400.json`、`p17b_b{20,50}_{base,guide}.json`、`run_p17.sh`、`run_p17b.sh`
